カメレオンサバイバー技術説明ガイド

このページは、専門展で技術の説明を担当する班員のための資料です。読み終えた班員の誰もが、「このゲームがどうやって動いているのか」を自分の言葉で説明でき、来場者の質問にも答えられることを目標にしています。

読み方: まず「最初に覚えること」と「展示での意図」を読み(約5分)、次に自分が担当するテーマの章を読み、最後に「想定Q&A」で答える練習をしてください。「最初に覚えること」の表と30秒の話す例は、班の全員が言えるようにしておいてください。

このページの内容は、2026年10月31日時点の最新版(最新コミット 51d4542)のプログラムをもとにしています。

一言で言うと

カメレオン役の1人が足元のマットを踏んで歩き、ほかの来場者がスマホを懐中電灯にして敵を照らし、全員で協力して夜の森から脱出するゲームです。

  • ゲーム本体は Unity 6 で作り、C# で書いています。
  • マットの状態は、マイコンの ESP32 がUSBシリアル通信でパソコンに送ります。
  • スマホはQRコードを読むだけで参加でき、最大7人まで遊べます。

圧力マットとESP32

マットを踏んだ向きが、どのようにゲームまで届くかを説明します。

足元には、前・後・左・右に1枚ずつ、合わせて4枚のマットがあります。ESP32 がどのマットが踏まれているかを GPIO で読み取り、1バイトのデータにまとめてUSBシリアル通信でパソコンに送ります。

話す例

足元には、前・後・左・右の4枚のマットが置いてあります。どのマットも、踏むと導通する(ONになる)スイッチとして働きます。ESP32 というマイコンが、4枚のマットのどれが踏まれているかを GPIO(入出力ピン)で読み取ります。ESP32 はその結果を8ビット(1バイト)のデータにまとめて、USBシリアル通信でパソコンに送っています。プレイヤーが前と右のマットを同時に踏めば、カメレオンは斜め右前に進みます。

  1. 各マットから出ている2本の線のうち、1本を ESP32 の GPIO に、もう1本を GND につなぎます。GPIO は INPUT_PULLUP(内蔵プルアップ抵抗を有効にした入力)に設定してあるので、マットを踏んでいない間は HIGH です。マットを踏むと GPIO が GND と導通して LOW になります。ESP32 は LOW を「踏まれた」と判定します(アクティブLOW)。
  2. 踏んだ瞬間や足を離した瞬間には、ON と OFF が短時間に何度も入れ替わるチャタリングが起きます。ESP32 は、同じ状態が15ミリ秒続いたときだけその状態を確定させるデバウンス処理で、チャタリングを取り除きます。
  3. ESP32 は4枚の状態を、1バイトのデータにまとめます。上位4ビットは識別用のマーカー 1010(0xA0)、下位4ビットは前・後・左・右の状態を表すビットフラグです。
  4. ESP32 は、状態が変化した瞬間と、変化がなくても0.2秒ごと(ハートビート)に、このデータをシリアル通信で送ります。ボーレート(通信速度)は115200bpsです。
  5. パソコンのゲームは、ESP32 がどの COMポートにつながっているかを自動で探します。正しい形式のデータを3回受信すると、ゲームはそのポートを ESP32 だと判定します。
  6. ゲームは、受け取った向きをキーボードの WASD キーと同じように扱います。マットとキーボードのどちらかで押されていれば、カメレオンはその向きに進みます。
例2進数意味
0xA01010 0000どのマットも踏まれていない
0xA11010 0001前のマットだけが踏まれている
0xA91010 1001前と右のマットが踏まれている(斜め右前に進む)

下位4ビットは、最下位ビットから順に 前(bit0=1)・後(bit1=2)・左(bit2=4)・右(bit3=8) です。GPIO の番号は、前が26、後が25、左が32、右が27です。なお、このマットは踏む強さは測っていません。踏まれているかどうか(ON/OFF)だけを読んでいます。

深掘りなぜ上位4ビットにマーカーを入れるのか

シリアル通信では、ESP32 の起動直後に、ブートログなど関係のないデータが流れてくることがあります。また、このゲームは動作確認のために、1,0,0,1 のようなテキスト形式も受け付けます。上位4ビットにマーカー 1010 を入れておくと、ゲームは本物のマットのデータだけを確実に識別できます。テキストの「0」「1」「,」「改行」の文字コード(0x30・0x31・0x2C・0x0A)は、どれも上位4ビットが 1010 にならないので、2つの形式が混ざっても誤認識しません。

深掘りなぜWi-FiではなくUSBにしたのか

班では最初、ESP32 からWi-Fi(UDPという通信)でデータを送る版を作りました。ところが、パソコンがつなぐWi-Fiが変わると、パソコンのIPアドレスも変わります。すると ESP32 は古いIPアドレスにデータを送り続けてしまい、「マットを踏んでもカメレオンが動かない」状態になりました。USBシリアル通信ならIPアドレスを設定する必要がなく、ケーブルをつなぐだけで動きます。Wi-Fi版のプログラムも、予備として残してあります。

深掘りケーブルが抜けたとき・データが途切れたとき
  • ゲームは、マットのデータが0.5秒届かなければタイムアウトとして「どのマットも踏まれていない」とみなします。そのため、通信が途切れても、カメレオンが勝手に歩き続けることはありません。
  • USBケーブルが抜けると、ゲームは2秒ごとに COMポートを再スキャンして ESP32 を探し直します。ゲームを起動する前につないでも、起動した後につないでも、ゲームは ESP32 を見つけられます。
  • タイトル画面とプレイ中の画面の左下には、「コントローラー: 接続中(USB COM3)」のような表示と、どのマットが踏まれているかの図が出ます。説明担当は、この表示でマットがつながっているかをすぐに確かめられます。

スマホが懐中電灯になる仕組み

来場者からの質問がいちばん多いテーマです。担当でない人も読んでおいてください。

スマホがQRコードで開くのは、ふつうのWebページです。そのページが JavaScript でスマホのジャイロセンサー(傾きセンサー)の値を読み、常時接続の通信(WebSocket)でパソコンへ送り続けます。

話す例

パソコンの中では、班で作った小さなWebサーバーが動いています。来場者がQRコードを読むと、そのサーバーからWebページが届くので、アプリを入れる必要はありません。ページはスマホのジャイロセンサーを読み、狙っている画面座標を1秒に約30回パソコンへ送ります。QRコードのURLは、Cloudflare Tunnel というサービスを使ってインターネット上に公開しています。そのため来場者は、会場のWi-Fiにつながなくても、5G回線のままで参加できます。

  1. ゲームを起動すると、cloudflared というプログラムが自動で動き、https://〜.trycloudflare.com/ というURLが作られます。ゲームはそのURLが本当に外から開けるかを確かめてから、URLをQRコードにして画面に出します。ここまでに30秒〜1分かかります。
  2. 来場者がスマホでQRコードを読むとページが開くので、「タップして始める」を押してもらいます。光の色は、8色のうち、いま誰も使っていない色が自動で割り当てられます(参加は最大7人なので、色が重なることはありません)。名前を入力する必要はありません。
  3. 来場者がスマホを傾けると、画面の狙いが動きます。狙いの上下はスマホの前後の傾き(ピッチ)で、左右はスマホを水平に回した角度(ヨー)で決まります。「中心をリセット」を押すと、その時の向きが基準(キャリブレーション)になり、画面の真ん中に対応します。
  4. 光がつくのは、来場者が「ライトON」を押している間だけです。ページは、スマホの向きとライトのON/OFFを、WebSocket で最大1秒に約30回送ります。
  5. パソコンは、スマホへ「今、敵に光が当たっている」「敵を倒した」という情報を返します。それを受け取ったスマホは、音を鳴らして震え、画面の撃破数を1つ増やします。

5G版(ふだんの起動方法)

play_night.bat で起動します。通信が Cloudflare Tunnel を経由するので、来場者のスマホは5G回線でも、どのWi-Fiからでも参加できます。URLはゲームを起動するたびに変わります。アカウントの登録は必要ありません。

同じWi-Fi版(インターネットがない会場)

play_night_wifi.bat で起動します。QRコードのURLは、パソコンのIPアドレス(例 https://192.168.x.x:8788/)になります。この方式では、パソコンとスマホを同じWi-Fiにつなぐ必要があります。5G版で起動しても、45秒たってトンネルができなかった場合は、ゲームが自動でこの方式に切り替えます。

深掘りCloudflare(クラウドフレア)と Cloudflare Tunnel とは？

Cloudflare は、CDN(コンテンツ配信ネットワーク)やセキュリティのサービスを提供しているアメリカの会社です。このゲームでは、Cloudflare の Cloudflare Tunnel という機能のうち、アカウント登録なしで使えるクイックトンネル(TryCloudflare)を使っています。「トンネル」は比喩ではなく、ネットワークの正式な用語です(ある通信を、別の通信の中に包んで運ぶことをトンネリングといいます)。

トンネルが必要な理由: 展示用のパソコンは、会場や家庭の LAN(ローカルネットワーク)の中にあり、ルーターの NAT やファイアウォールの内側にいます。そのため、インターネット側(例えば5G回線のスマホ)から、パソコンへ直接接続(インバウンド接続)することはできません。

トンネルの仕組み: ゲームが起動した cloudflared は、パソコンから Cloudflare のサーバーへアウトバウンド接続(内側から外側への接続)を張ります。アウトバウンド接続は、ふつうのWeb閲覧と同じ向きの通信なので、多くのネットワークで許可されています。Cloudflare は、このパソコン用に https://〜.trycloudflare.com/ というURLを発行します。スマホがこのURLにアクセスすると、Cloudflare のサーバーがリバースプロキシとして動き、張ってある接続を通してリクエストをパソコンへ転送します。cloudflared は受け取ったリクエストを、パソコンの中の自作Webサーバー(http://127.0.0.1:8787)へ渡します。

深掘りWebSocket とは / なぜ使うのか

ふつうのWebの通信(HTTP)は、「スマホがリクエストを送り、パソコンのレスポンスを待つ」というリクエスト/レスポンス型です。これを1秒に30回くり返すと、接続の確立とレスポンス待ちの時間が積み重なり、光がカクカク動いてしまいます。WebSocket は、一度確立した接続を維持したまま(常時接続)、双方向に、レスポンスを待たずにデータを送れるプロトコルです。そのため、インターネットを経由してもレイテンシが小さく、動きも安定します。

スマホのブラウザで WebSocket が使えないときは、ページが自動で HTTP の POST /pointer(1秒に約20回)にフォールバックします。また、回線が混んで送信待ちのデータ(送信バッファ)がたまったときは、ページは古い座標を破棄して最新の座標だけを送ります。こうして、遅延が累積するのを防いでいます。

深掘りなぜWebサーバーを自作したのか

.NET には、Webサーバーを作るためのクラス(HttpListener)が用意されています。しかし、Windows ではこのクラスが管理者権限や URL予約(netsh http add urlacl)を求めることがあります。班は、展示用のパソコンで何も設定せずに動かしたかったので、TCP ソケットを直接扱う TcpListener だけを使い、HTTP・HTTPS(TLS)・WebSocket のプロトコル処理を自分たちで実装しました。PointerServer.cs は約2,000行あり、スマホに配るページ(HTML と JavaScript)もこのファイルの中に入っています。

深掘り傾きから狙いの位置を出す計算

ゲームは、スマホの向きのベクトルを、スマホの正面に置いた仮想の平面に投影して狙いの位置を計算します(透視投影)。角度 θ のときの平面上の位置は tan(θ) に比例するので、角度に比例させる線形の対応とは違い、狙いは画面の中心付近ではゆっくり、外側ほど速く動きます。これは、実際の物を指したときの見え方と同じ対応です。

角度は ±80° で止めています。tan() は、角度が90°に近づくと値が無限に大きくなるからです。また、左右の角度は 0° と 360° の境目で値が急に飛ぶので、ゲームは角度の差を −180°〜180° の範囲に直してから使います。

深掘りスマホを動かさなくても光や画面が消えない理由
  • スマホを動かしていない間も、ページは0.25秒ごと(ライトON中は0.1秒ごと)に最後の状態をハートビートとして送り続けます。そのため、パソコンはそのスマホを「接続中」のまま扱い、光も消えません。
  • スマホの結果画面には「続けてプレイする」と「終了する」のボタンがあります。「終了する」を押すと、パソコンはその人をすぐ参加者から外し、色と参加の枠を空けます。
  • あるスマホから10秒間何も届かなければ、パソコンはタイムアウトとしてその人が抜けたとみなし、参加の枠(スロット)を1つ解放します。7人が参加しているときに8人目が参加しようとすると、スマホに「満員です(最大7人)」と表示されます。
  • Android のスマホは、画面が消えるとWi-Fiが省電力モードになり、送信が遅れます。これを防ぐため、ページは Screen Wake Lock API で画面の消灯を止めています。

光の当たり判定

スマホの向きが森の中のどの場所になるのか、そして光でなぜ敵が倒れるのかを説明します。

ゲームは、スマホが狙っている画面座標から、カメラの奥へレイ(半直線)を飛ばします(レイキャスト)。レイが地面と交差した点が「照らしている場所」になります。

  1. ゲームは、スマホから届いた狙いの位置を受け取ります。この位置は、画面の横と縦をそれぞれ0〜1で表した正規化座標(ビューポート座標)です。
  2. ゲームは、カメラからその座標の方向へレイを飛ばします。この処理をレイキャストといい、Unity の Physics.Raycast を使っています。
  3. レイが地面や物のコライダー(当たり判定の形)と交差した点(ワールド座標)が、そのスマホの「照らしている場所」です。ゲームはそこに、スポットライトとスマホごとの色の輪を表示します。
  4. 照らしている場所から半径の内側にいて、高さの差が1.8未満の敵は、「光の体力」が減っていきます。光の体力が0になると、その敵は倒れます。
  5. 複数の人が同じ敵を照らすと、重ねた人数の分だけダメージが増えます(2人なら2倍)。途中で光を外しても、敵の体力は元に戻りません。

1人分の光の半径は、3.0m × 1/√人数 で決まります(ただし1.1mより小さくはなりません)。人数が増えたときにゲームが簡単になりすぎないよう、1人分の光を小さくしています。人数でそのまま割らずに√を使ったのは、人数が増えたときに光が急に小さくならないようにするためです。

話す例

スマホが狙っている画面の位置から、カメラの奥へレイを飛ばすレイキャストという方法で、レイが地面と交わった点を「照らしている場所」にしています。光の円の中にいる敵は体力が減っていき、0になると倒れます。参加する人数が多いほど1人分の光が小さくなるので、何人で遊んでもちょうどいい難しさになります。

深掘り光のほかに敵にダメージを与えるもの
  • 雷(閃光): 約12秒ごとに落ちます。落ちる少し前にゴロゴロと予告の音が鳴り、森全体が一瞬明るくなって、カメレオンから26m以内にいる敵にダメージを与えます。体力の低い妖精は、雷1回で倒れます。
  • ランタン: ゲームの最初から灯っています。ランタンから8.5m以内にいて、ランタンから見通せる場所にいる敵に、毎秒ダメージを与えます。敵がランタンに近いほど、ダメージは大きくなります。

深掘り色の決め方と、敵が見失う仕組み

カメレオンのすぐ近くに木や岩があれば、ゲームはカメレオンの体の色をその木や岩の色に近づけます。広場や通路の上にいるときは、地面の色と模様に近づけます。色は一瞬で変わるのではなく、なめらかに変わります。

擬態している間は、画面の縁が水色に光ります(文字ではなく画面の演出で伝えています)。擬態ゲージは、カメレオンの頭の上のバーに出ます。

擬態が始まると、ゲームはすべての敵の追跡目標(ターゲット)を解除します。敵は、近くの通路を歩いては立ち止まって見回す動きに切り替わり、狐も火の玉を撃たなくなります。擬態が解けると、カメレオンから16m以内にいる敵が「！」を出し、ふたたびカメレオンを追いかけ始めます。

敵のAI(追いかけ方)

ここでいう「AI」は、敵の追いかけ方を決めるプログラムのことです。学習するタイプのAIではありません。

敵は、カメレオンへの視線が通れば直進します。通らなければダイクストラ法で最短経路を探索して回り込みます。壁に当たったときは、進む角度を少しずつ変えて壁沿いに進みます。

  1. 視線が通るときは直進する: 敵とカメレオンを結ぶ線分がすべて歩行可能な領域にあれば(視線判定、ライン・オブ・サイト)、敵はカメレオンに向かって直進します。視線判定は計算コストが高いので、結果を0.15秒間キャッシュしています。
  2. 視線が通らないときは経路探索する: ゲームはマップの通路を、ノード(分岐点・曲がり角)とエッジ(通路)からなるグラフで表し、ダイクストラ法で最短経路を求めます。敵はその経路のウェイポイント(中継点)を順にたどります。経路は0.4秒ごとに再計算します。
  3. 壁に当たったら沿って進む(ウォールスライド): 進みたい方向が通路の外になるとき、敵は向きを 0° → ±20° → ±40° → ±65° → ±90° → ±125° の順に曲げて、歩ける向きを探します。それでも0.3秒以上進めなかった場合は、0.8秒の間だけ、計算した道に従って進みます。

深掘りダイクストラ法を一言で

ダイクストラ法は、重み付きグラフの最短経路問題を解くアルゴリズムです。スタートのノードから距離が近いノードの順に、そこまでの最短距離を1つずつ確定させていきます。このゲームでは、通路の分岐点や曲がり角をノード、ノード間の通路をエッジ、通路の長さをエッジの重みとしたグラフの上で計算しています。導きの花が出す「光の道」も、同じ計算で作っています。

深掘りマップのデータを使い回す工夫

マップは「通路(線分)」と「広場(円)」を組み合わせて作っています。ゲームは同じマップのデータから、見た目の地面、歩ける場所の判定、敵の道案内の3つをすべて作ります。そのため、見た目の地面と実際に歩ける場所がずれることがありません。木や岩は、マップごとに固定したシード値の擬似乱数で配置しています。シード値が同じなら乱数の並びも同じなので、同じマップは何度遊んでも同じ景色になります。

  2. Meshy AI を使って、その絵から3Dモデルを作りました。ただし、この時点のモデルにはリグもアニメーションもなく、メッシュ(形)とテクスチャ(色)のデータしかありません。
  3. 元のモデルは4.5万〜20万ポリゴンと重かったので、Blender(3DCGソフト)をヘッドレス(GUIなし)で実行する Python スクリプト(blender/enemies/rig_enemy_ghosts.py)で、5,000〜8,000ポリゴンまで削減しました。テクスチャも1024×1024pxに縮小しています。削減の方法は、下の「深掘り」で説明します。
  4. 同じスクリプトが、モデルにボーンを8本自動で配置します(リギング)。スクリプトは各頂点の位置から「どのボーンがどの頂点をどれだけ動かすか」(スキンウェイト)を計算して割り当て、歩く・噛みつく・パンチする・火の玉を投げるアニメーションもキーフレームで自動生成します。
  5. Unity はモデルを読み込んだ後に高さを測り、種類ごとに決めた大きさ(熊4.4・狐2.6・妖精2.1・狼1.5)に自動でそろえます。歩くアニメーションと攻撃するアニメーションは、0.13秒のクロスフェードで切り替えます。
話す例

キャラクターは、まず画像生成AIで絵を描き、Meshy というAIでその絵を3Dモデルにしました。ただ、そのままではリグもアニメーションもないので、Blender という3DCGソフトを Python で操作してボーンを入れ、歩いたり攻撃したりするアニメーションを自動で付けています。また、元のデータはポリゴン数が多すぎたので、Blender の Decimate という機能でポリゴン数を元の数十分の1まで削減しました。これで、敵がたくさん出てきてもゲームが重くなりません。

深掘りポリゴン数をどうやって減らしたのか

Blender のDecimate(デシメート)モディファイアを、Python スクリプトから使いました。手作業でポリゴンを消したわけではありません。

  1. スクリプトは、まず元のモデルのポリゴン数を数えます。
  2. 次に、キャラクターごとに決めた目標のポリゴン数(熊7,000・狐6,000・妖精5,000・狼5,000)を元のポリゴン数で割り、削減率(ratio)を計算します。例えば元が10万面で目標が5,000面なら、残す割合は0.05(5%)です。
  3. この ratio を Decimate の Collapse モードに指定すると、Blender はエッジコラプス(辺の両端の2頂点を1つに統合する処理)を、形状の誤差が小さい辺から順にくり返します。こうして、全体の形状を保ったままポリゴン数が減ります。
  4. ポリゴンを減らすと、頂点法線で補間するスムーズシェーディングでは陰影が乱れます。そこで、カスタム法線を消去してからフラットシェーディング(面ごとに1つの法線で陰影を付ける方式)に切り替え、ローポリ調の見た目にそろえました。

テクスチャも、同じスクリプトで1024×1024ピクセルに縮小しています。ポリゴン数とテクスチャ解像度の両方を下げたので、ノートパソコンの内蔵GPUでも敵が何十体出て動きます。

難しさとスコア

遊ぶほど難しくなる仕組みと、スコアの付け方を説明します。

カメレオンがホタルをつかまえたり、体力を回復したりするたびに「脅威レベル」が上がり、敵が多く、速く出てくるようになります。

ゴールまでの流れ

  1. 灯り役が、ホタルの石を1人なら合計10秒照らします。照らす人数が多いほど早くたまり、2人なら5秒です。途中で光を外しても、それまでに照らした時間は残ります。
  2. ホタルが集まった石にカメレオンがさわると、ホタルを1匹つかまえられます。
  3. ホタルが2匹そろうと、スタート地点の門が開きます。カメレオンが門を通ればクリアです。

道に迷ったときは、灯り役が導きの花を0.6秒照らします。すると、いちばん近い石(ホタルが2匹そろった後は門)までの光の道が地面に出ます。また、カメレオンのまわりには、行き先の方向を指す矢印も表示されます。

だんだん難しくなる仕組み

  • 敵が現れる間隔は、最初は2.4秒です。時間がたつにつれて短くなり、最短で0.7秒になります。
  • カメレオンがホタルをつかまえると、脅威レベルが1上がり、その場に敵の群れが押し寄せます。
  • 倒した敵は、50%の確率で緑の回復オーブを落とします。カメレオンがオーブで合計90回復するたびに、脅威レベルが1上がります。
  • 脅威レベルは最大9です。レベルが1上がるごとに、敵が現れるペースが16%上がり、同時に出せる敵の数の上限が5体増えます。

チュートリアル(練習モード)

タイトル画面では、まず「チュートリアルから始める」を選べます(「スキップ」で本番の難易度選択へ進むこともできます)。チュートリアルは専用のマップ「チュートリアルの森」で、次の4つのステップを順に進めます。

  1. 移動しよう: カメレオン役が、マットを踏んで広場のまん中の光るスポットまで歩きます。
  2. 敵を倒そう: 台座の上に4種類の敵が1体ずつ現れます。灯り役がライトで合計10体倒します。練習の敵は追いかけてこず、倒すと4秒後に同じ場所に復活します。
  3. ホタルを集めよう: 奥の石を照らしてホタルを呼び、カメレオンが触れて捕まえます。
  4. 門から脱出しよう: 開いた門をくぐるとクリアです。

チュートリアルには、雷・脅威レベル・ダメージ・回復オーブ・ランキングはありません。終わると、そのまま難易度(マップ)を選んで本番を始められます。スマホはつながったままなので、灯り役はQRコードを読み直す必要がありません。

深掘りスコアの式に込めた考えと、ランキングの保存

スコアの式は、敵を1体倒すこと(100点)と、10秒早く脱出すること(100点)が同じ価値になるように作っています。こうすることで、「急いで脱出する」遊び方と「敵をたくさん倒す」遊び方のどちらかだけが有利にならないようにしています。スコアが同じ場合は、早く脱出した方が上の順位になります。

記録は、ゲームと同じフォルダにある ranking.csv に保存されます。このファイルは、Excel で開いても文字化けしない形式(BOM付きUTF-8)です。Excel で名前を直したり行を消したりして保存すると、ゲームがタイトル画面に戻ったときにその変更が反映されます。画面には、マップごとに上位10件の記録を表示します。

作り方の工夫

来場者に「どうやって開発したの？」と聞かれたときに使う内容です。

場面をプログラムで組み立てる

Unity では、ふつうはエディタ上でシーンにオブジェクトを手で配置します。このゲームでは手で配置せず、エディタ拡張のスクリプト NightSceneBuilder が毎回ゼロからシーンを生成します。こうすると、誰がビルドしても同じシーンになり、班員が同時に作業しても Git でシーンファイルのコンフリクト(変更の衝突)が起きにくくなります。

ダブルクリックで最新版を起動

バッチファイル play_night.bat をダブルクリックすると、Unity をバッチモード(GUIなし)で実行して最新のプログラムをビルドし(約1分)、そのまま起動します。

ゲームに自動で遊ばせて撮影する

コマンドライン引数 -nightAutoShot を付けてゲームを起動すると、ゲームが自動操作しながら、タイトル・敵を照らす場面・擬態・結果画面などのスクリーンショットを順番に保存します。これにより、人が操作しなくても見た目の確認(ビジュアルテスト)ができます。

効果音はプログラムで作る

ゲーム内の効果音(照らしたときのブザー、敵を倒したときのチャイム、雷など)は、音声ファイルを使わず、波形をプログラムで合成して作っています(プロシージャルオーディオ)。音声ファイルを使っているのは、BGMとスマホの一部の音だけです。

先にモックアップを作ってから決める

画面の配置やランキングの表示は、先にHTMLでモックアップ(試作の画面)を作り、班で見比べて決めました。決まってから Unity で作ったのは、作り直しを減らすためです。

苦労した話

来場者からは「難しかったことは？」とほぼ必ず聞かれます。少なくとも1つは、自分の言葉で話せるようにしておいてください。

光が当たった物を光らせようとしたのに、画面が変わらなかった

症状
班は、Unity の「発光(Emission)」という機能で、光が当たった物を黄色く光らせようとしました。ところが、ビルドしたゲームでは、何をしても見た目が変わりませんでした。
調べ方
ログで確かめると、色の値は正しく設定されていました。そこで、発光の色にありえない色(マゼンタ)を入れて試しました。それでも画面は白いままだったので、発光そのものが描かれていないことが確定しました。それまで敵が光って見えていたのは、敵の元の色がたまたまオレンジだったからでした。
対策
発光を使うのをやめ、必ず描かれるふつうの色を、直接黄色に近づける方法に変えました。
学び
数字が正しくても、それが画面に出ているとは限りません。結果がはっきり分かる実験をして、原因を切り分けることが大切です。

スマホを動かしてから、光が遅れて動いた

原因
スマホがデータを1回送るたびに、TCP の接続を確立し直していました。1秒に20回、TCP の接続確立(3ウェイハンドシェイク)と、HTTPS の場合は TLS ハンドシェイクまでくり返していたことが原因でした。
対策
まず、接続を再利用する HTTP Keep-Alive と、小さなパケットをまとめて送る Nagle アルゴリズムを無効にする設定(NoDelay)を入れました。さらに WebSocket に変えて、接続を常時維持するようにしました。Android の省電力で送信が遅れる問題には、Screen Wake Lock API で画面の消灯を止めて対応しました。
学び
遅延の原因は、計算の速さではなく、接続の確立のしかたにありました。

iPhone だけ傾きセンサーが使えなかった

原因
iPhone は、HTTPS(暗号化された通信)で開いたページにしか、傾きセンサーの使用許可を出しません。
対策
班は、Windows の PowerShell で自己署名証明書を作り、HTTPS のサーバーも用意しました。今は Cloudflare のURLが最初から HTTPS なので、ブラウザに警告も出ません。

敵が曲がり角で止まってしまった

原因
敵は最短距離で直進しようとして、歩行可能な領域からはみ出していました。はみ出した敵を領域の内側へ戻す補正処理が、敵を元の位置に押し戻し続けていたため、敵が動けなくなっていました(スタック)。
対策
敵が通路からはみ出す前に、通れる方向へ少しずつ向きを曲げ、壁沿いに滑らせるようにしました。それでも動けない場合は、しばらく計算した道に従って進ませます。

地面に線やちらつきが出た

原因
似た見た目の不具合が4回起き、4回とも原因が違いました。1回目は、メッシュを生成するときの三角形の頂点の巻き順(ワインディングオーダー)の間違いでした。2回目は、カメラのニアクリップ面が0.1と近すぎて、深度バッファの精度が手前に偏っていたことでした。3回目は、葉のメッシュが地面に埋まっていたことでした。4回目は、隣り合う通路がまったく同じ高さで重なり、Zファイティングが起きていたことでした。
対策
1つずつ原因を切り分けて直しました。例えば、ニアクリップ面を3に広げ、通路ごとに高さを2mmずつずらしました。
学び
見た目が似ている不具合でも、原因が同じとは限りません。

会場のWi-Fiだとスマホがつながらなかった

原因
最初の版では、パソコンとスマホを同じWi-Fiにつなぐ必要がありました。しかし、学校やゲスト用のWi-Fiは、端末どうしの通信を禁止していることがあります。これを AP アイソレーション(クライアント分離)といいます。また、Wi-Fiが変わるとパソコンのIPアドレスが変わり、QRコードのURLも変わってしまいます。
対策
Cloudflare Tunnel でインターネット上にURLを公開し、スマホが5G回線からも参加できるようにしました。インターネットがない会場のために、同じWi-Fi版も残しています。

マットを踏んでも反応しないまず、画面左下が「接続中」になっているか、踏んだマットが図で光るかを見てください。接続中なのに動かない場合は、マットの配線とピンを確認します。応急処置として、キーボードの WASD キーでもカメレオンを動かせます。
ゲーム画面が出てこないゲームのウィンドウが、ほかのウィンドウの裏に隠れている可能性があります。タスクバーの「カメレオンサバイバー」をクリックしてください。
ノートパソコンの電池がすぐ減るこのゲームは動作中に約20Wの電力を使います。電池だけでは1時間半ほどしかもたないので、電源アダプターをつないでおいてください。

用語ミニ辞典

説明で使う言葉を、来場者に分かる言葉で言い換えられるようにしておいてください。

Unity(ユニティ)
ゲームを作るためのソフト(ゲームエンジン)です。3Dの表示、当たり判定、音などの機能がそろっています。
C#(シーシャープ)
Unity でゲームのプログラムを書くときに使う言語です。
ESP32
Espressif 社のマイコンで、Wi-Fi と Bluetooth を内蔵しています。このゲームでは、Wi-Fi ではなくUSBシリアル通信でパソコンとつないでいます。
マイコン
マイクロコントローラーの略です。CPU・メモリ・入出力ピンを1つのチップにまとめた、機器の制御用のコンピューターです。
ビット / バイト
ビットは0か1の1けたで、8ビットで1バイトです。マット4枚の状態は4ビットで表せるので、残りの4ビットは識別用のマーカーに使っています。
シリアル通信(USB)
1本の線で、データを1ビットずつ順番に送る方法です。115200bps は、1秒に115200ビット送れるという意味です。
チャタリング
スイッチを押した瞬間や離した瞬間に、ON と OFF が細かく何度も入れ替わる現象です。
Webサーバー
HTTP のリクエストを受けて、Webページなどをレスポンスとして返すプログラムです。このゲームでは、班で自作したWebサーバーがゲームの中で動いています。
WebSocket
HTTP から切り替えて確立し、接続を維持したまま双方向にデータを送り合えるプロトコルです。チャットやオンラインゲームでも使われています。
HTTPS / サーバー証明書
HTTPS は、HTTP を TLS で暗号化した通信です。サーバー証明書は、認証局がサーバーの正当性を電子署名で保証するデータです。自分で署名したものは自己署名証明書といい、ブラウザに警告が出ます。
Cloudflare / Cloudflare Tunnel
Cloudflare は CDN やセキュリティのサービスを提供する会社です。Cloudflare Tunnel は、LAN の中にあるパソコンを、ポート開放なしでインターネットに公開する機能です。このゲームは、登録不要のクイックトンネルを使っています。
IPアドレス
ネットワーク上で機器を識別する番号です。DHCP で割り当てられるので、つなぐWi-Fiが変わると変わります。
ジャイロセンサー
回転の速さ(角速度)を測るセンサーです。スマホのブラウザは、ジャイロセンサーや加速度センサーの値から計算した向きを DeviceOrientation イベントで渡します。
レイキャスト
ある点からある方向へレイ(半直線)を飛ばし、最初に交差するコライダーとその交点を求める処理です。
ダイクストラ法
重み付きグラフで、あるノードからほかのノードまでの最短経路を求めるアルゴリズムです。
Meshy AI
絵や文章から3Dモデルを作ってくれるAIのサービスです。
Blender
無料で使える3Dソフトです。Python のプログラムで操作することもできます。
Decimate(デシメート)
Blender のモディファイアの1つで、形状をなるべく保ったままポリゴン数を削減します。Collapse モードではエッジコラプスを使います。
ボーン / リグ / スキンウェイト
ボーンは3Dモデルを変形させるための骨組みで、ボーンの構造全体をリグといいます。スキンウェイトは、各頂点がどのボーンにどれだけ追従するかを表す値です。
ポリゴン(面)
3Dモデルの表面を作っている三角形です。数が多いほど形が細かくなりますが、表示が重くなります。
FPS
画面を1秒間に描き直す回数です。このゲームは、テストで約90でした。
CSV
値をカンマで区切って並べた、表のファイルです。Excel で開けます。
Zファイティング
同じ深度にある2つの面が重なり、深度バッファでの前後判定がフレームごとに入れ替わって、ちらついて見える現象です。
Git / プルリクエスト
Git は変更の記録を残す仕組みです。プルリクエストは、変更を取り込む前に、ほかの人に確認してもらう手順です。
